## 二、为什么这么做（Why）

**动机**：阶段 1 有了「循环」，阶段 2 补上「人能看到的两条通路」——输入进来、画面出去。核心是把约束 D1/D3/D4 从文字变成可运行代码，同时验证阶段 1 的 `PostTask` / `PostRepeatingTask` / `Stop()` 真的能撑起一个 TUI。

**对应约束编号：**
- `D1` legacy 主路径 → `LegacyConsoleBackend` 用 `WriteConsoleOutputW`；`ConsoleSession` 用 `ReadConsoleInput`。
- `D2` VT 仅可选后端 → 抽象成 `IRenderBackend`，但**本阶段不实现 VT**，默认/唯一主路径是 legacy；`MemoryBackend` 是测试后端，不是 VT。
- `D3` 必须 dirty-cell 差分 → `ScreenBuffer` 双缓冲 + `Commit()` 只产出变化单元格。
- `D4` 渲染按 tick 合并 → `Renderer::RenderTick()` + `PostRepeatingTask(16ms)`；输入不直接刷屏。
- `D5` resize/鼠标 → `ConsoleSession` 设 `ENABLE_WINDOW_INPUT | ENABLE_MOUSE_INPUT`，`InputDecoder` 解 `WINDOW_BUFFER_SIZE_EVENT` / `MOUSE_EVENT`。
- `D6` 内部 UTF-16 → `Cell.ch` 是 `wchar_t`，与 `CHAR_INFO.UnicodeChar` 对齐。
- `D7` 仅 ASCII → `InputEvent.Describe()` 只对 32..126 显示字符，其余显示 VK 名；不做 IME/组合键。
- `B1`/`B2`/`B7` → 输入线程只 `Decode` + `PostTask`，不碰渲染状态；渲染只在 loop 线程。
- `A1`/`A4` → 零第三方依赖，测试框架自建。
- `F5` → 14 个测试 + `--selftest`。

**被放弃的方案及原因：**

| 放弃 | 原因 |
|---|---|
| VT/ANSI 转义序列做主渲染 | 约束 D1 明确要求 legacy 主路径；VT 会绕过双缓冲差分这一最有学习价值的部分 |
| 每次输入事件后立即 `WriteConsoleOutput` | 违反 D4；高吞吐下闪烁 + 大量系统调用。改为「标脏 → tick 合并 → 差分」 |
| 每帧全屏重绘 | 违反 D3；`ScreenBuffer` 只写变化单元格，第二帧只改 1 格就只产 1 个 delta |
| `GetStdHandle(STD_OUTPUT_HANDLE)` 直接当画布 | 会污染调用者滚动历史；改为 `CreateConsoleScreenBuffer` 建自己的活动缓冲并恢复 |
| 让输入线程直接调用 `Renderer::Put` | 违反 B1/B7（跨线程碰 loop 状态）；改为解码后 `PostTask` 回投 |
| 用 `CancelSynchronousIo` 作为唯一停止手段 | 对控制台输入句柄不总是可靠；主用 `WriteConsoleInput` 注入哨兵记录，`CancelSynchronousIo` 仅兜底 |
| 依赖人工在真实控制台里点按键来验证 | 本执行环境的控制台被重定向（std 句柄是管道），交互式画面不可见；因此做 `--selftest` 用同一套逻辑脚本化验证 |

**这个决定让哪件事变得可见：**
1. **「不撕裂」的真正含义**：一帧只有一次 `Present`，且 `Commit` 保证前后缓冲一致后才交换；多个 source 在一 tick 内的改动被合并成一帧。
2. **Windows 没有 epoll 的第二个后果**：阻塞的 `ReadConsoleInput` 没有干净取消 API，得用「往输入队列注入一条假记录」这种 Win32 特有技巧唤醒——这比 Unix 的 self-pipe 更绕，但正是要学的东西。
3. **差分 + run-length 合并**：`LegacyConsoleBackend` 把同一行连续的脏单元格合并成一次 `WriteConsoleOutputW`，把系统调用数从「单元格数」压到「行数级」。

## 三、怎么做的（How）

### 3.1 关键数据结构

**`ScreenBuffer`（双缓冲）**
```
front_ : 上一次 Present 的内容（屏幕现状）
back_  : 本帧 Draw 的目标内容
dirty_ : 本帧被 Put 过的位置（避免每帧 O(w*h) 全扫描）
force_full_ : Resize 后置位，强制整屏输出（清旧内容残留）
```
`Commit()`：`force_full_` 时输出全部单元格；否则只检查 `dirty_` 位置，`front_[i] != back_[i]` 才产 `CellDelta`，随后 `front_ = back_`。

**`CellDelta` / run-length**：`LegacyConsoleBackend::Present` 把 deltas 按 `(y,x)` 排序，把「同一行且 x 连续」的分组成 `Run`，每个 run 一次 `WriteConsoleOutputW`。

**`InputEvent`**：把 5 类 `INPUT_RECORD`（KEY/MOUSE/WINDOW_BUFFER_SIZE/FOCUS/MENU）统一成带 `kind` 的结构，`Describe()` 生成日志行。

### 3.2 核心流程 / 调用链

```
[输入线程]                         [loop 线程]                    [渲染 tick]
ReadConsoleInputW (阻塞)
   │ 32 条/批
   ▼
Decode(rec) → InputEvent
   │
   └─ cb(e) = loop.PostTask([e]{ ... })  ──►  DispatchPostedTasks
                                                │ OnInputEvent(e) 改状态
                                                │ Draw() 改 back_ + MarkDirty
                                                ▼
                              PostRepeatingTask(16ms) ─► renderer.RenderTick()
                                                          │ dirty_?
                                                          ├─ 否 → 不刷（合并/无操作帧）
                                                          └─ 是 → buffer_.Commit() → deltas
                                                                    └─ backend.Present(deltas)
                                                                         └─ Legacy: run-length 合并写
```

`ESC` / `Ctrl+C` → `OnInputEvent` 返回 true → `loop.Stop()` → `input.Stop()`（注入哨兵 → join）→ 恢复 console mode / 活动缓冲 / 光标。

### 3.3 用到的 Win32 API

| API | 用途 |
|---|---|
| `CreateFileW(L"CONIN$"/L"CONOUT$")` / `GetStdHandle` | 拿控制台输入/输出句柄 |
| `GetConsoleMode` / `SetConsoleMode` | 保存恢复 mode；开 `ENABLE_WINDOW_INPUT`/`ENABLE_MOUSE_INPUT`，关行输入/回显/自动换行 |
| `CreateConsoleScreenBuffer` / `SetConsoleActiveScreenBuffer` | 建自己的活动缓冲，不污染调用者历史 |
| `GetConsoleScreenBufferInfo` / `SetConsoleScreenBufferSize` | 查询/同步尺寸（resize） |
| `GetConsoleCursorInfo` / `SetConsoleCursorInfo` | 隐藏/恢复光标 |
| `ReadConsoleInputW` / `WriteConsoleInputW` | 读输入记录；**注入哨兵记录以唤醒阻塞读** |
| `WriteConsoleOutputW` | 按 run 写入 `CHAR_INFO` 单元格（主渲染路径） |
| `CancelSynchronousIo` | 停止输入线程时的兜底取消 |
| `CHAR_INFO` / `INPUT_RECORD` / `SMALL_RECT` / `COORD` | 控制台数据结构 |

### 3.4 遇到的坑与处理（真实发生）

| 坑 | 现象 | 处理 |
|---|---|---|
| **嵌套 lambda 捕获** | `key_viewer_main.cpp` 内层 `PostTask` lambda 用了 `session`，但显式捕获列表没带它 → `error C3493 / C2326` | 把 `&session` 加进捕获列表 |
| **`wchar_t` 无法流入 `ostringstream`** | 测试框架 `Str(wchar_t)` 触发「引用已删除的 `operator<<`」→ `error C2280 / C2088` | `Str()` 用 `if constexpr (is_same_v<T,wchar_t>)` 转码点数字输出 |
| **resize 后旧内容残留** | 尺寸变化时 front_/back_ 都被重置成默认值，`front==back` 会跳过所有单元格，真实控制台上旧画面不会被清掉 | 引入 `force_full_` 标志：Resize 后首帧无条件输出全部单元格（第一次尝试用「哨兵值」很脆弱，改成显式分支） |
| **首帧「全默认」不产 delta** | `renderer_resize_reemits_full_frame` 测试里 `Clear(Cell{})` 首帧 0 delta → History 少一帧，断言 2 实际 1 | 测试改用非默认首帧；这恰好印证了差分的正确行为（写相同值不产 delta） |
| **`CONIN$` 与 `CONOUT$` 是同一句柄** | 探针显示两者都返回 `0x620`（conhost 映射到活动缓冲） | 不假设句柄不同；`ConsoleSession` 分别打开、各自保存/恢复 mode |
| **输入线程无干净取消** | `ReadConsoleInput` 阻塞，直接 join 会挂死 | 主用 `WriteConsoleInputW` 注入 `VK=0,ch=0` 哨兵记录，线程读到即退出；`CancelSynchronousIo(thread_handle)` 兜底 |
| **本环境控制台被重定向** | `GetConsoleMode` 在 std 句柄上失败（是管道），但 `CONOUT$` 是 `FILE_TYPE_CHAR`、`WriteConsoleOutputW` 成功 | 做成双模式：真实控制台走 legacy，`--selftest` 用 `MemoryBackend` 驱动同一套 `KeyViewer` 逻辑，保证无控制台也能验证出口条件 |
| **MSVC `/showIncludes` 噪音** | 编译时刷屏「注意: 包含文件」 | 与代码无关（环境注入），构建输出重定向到文件后不影响结果 |

### 3.5 线程 / 生命周期时序

```
主线程            输入线程              loop 线程           渲染 tick(同 loop 线程)
  │ ConsoleSession 构造（接管 mode/缓冲）
  │ Renderer/KeyViewer 构造
  │ input.Start() ────► 阻塞在 ReadConsoleInputW
  │ loop.Run() ───────────────────────► Wait(Waker)
  │                      │ 用户按键
  │                      │ Decode → InputEvent
  │                      └─ PostTask ──► SetEvent 唤醒
  │                                       │ OnInputEvent(改状态)
  │                                       │ Draw(改 back_ + MarkDirty)
  │                                       ▼
  │                              (16ms tick) RenderTick → Commit → Present
  │                      │ ESC
  │                      └─ PostTask ──► loop.Stop()
  │                                       │ 退出循环，排空
  │◄──────────────────────────────────────┘ Run() 返回
  │ input.Stop() ──► 注入哨兵 → join
  │ ConsoleSession 析构（恢复 mode/缓冲/光标）
```

注意：**渲染 tick 也在 loop 线程**（`PostRepeatingTask` 的回调在 loop 分发），因此 `Renderer` / `ScreenBuffer` / `KeyViewer` 全程单线程，无锁——约束 B1 的又一次兑现。

## 六、遗留 / 下一阶段衔接

**遗留：**
- **VT/ANSI 后端未实现**（约束 D2 允许但本阶段不做）。抽象已备好，需要时加一个 `VtBackend` 即可，默认仍为 legacy。
- 本执行环境的控制台被重定向，真实交互画面无法在此截图验证；`--selftest` 覆盖了逻辑正确性，但**建议在真实 Windows Terminal / conhost 里手动跑一次 `key_viewer.exe`** 看实际渲染效果。
- `LegacyConsoleBackend` 的 `LastCallCount()`（run 数）目前只在代码里统计，未写进测试断言；后续做性能对比时可加。
- `ConsoleSession::RefreshSize` 对新活动缓冲调 `SetConsoleScreenBufferSize`，若窗口比目标小会失败——真实 resize 场景下应改为以「窗口最大值」为准，阶段 3 再打磨。
- 编码边界：内部 UTF-16，第一版只保证 ASCII；中文/emoji/代理对未处理（约束 D6/D7 已明确列为非目标）。
- `/showIncludes` 编译噪音来自本机 MSVC/CMake 环境，未查明根因，不影响构建。

**下一阶段（阶段 3：I/O 后端）需要本阶段提供的接口：**
- `EventLoop::PostTask` / `PostRepeatingTask` / `Stop()` —— IOCP completion 回投、渲染 tick、优雅退出都复用。
- `Renderer` / `KeyViewer` —— 目录监视 / 文件 tail 的数据可以画进同一画面。
- `ConsoleSession::Output()` —— 若做 VT 后端会用到；legacy 路径已封装好。

**需要提前注意的坑：**
- 阶段 3 用 `GetQueuedCompletionStatusEx` 替换 `Waker::Wait` 时，`RunIteration` 的「分发 → 计算 timeout → 等待」结构保持不变；输入线程依旧只投递 completion，不得直接调业务回调（约束 B2）。
- close 状态机（`active → closing → 排空 → 释放`）要复用本阶段「哨兵唤醒 + 排空 + join」的优雅关闭套路。
- 高吞吐 source 进来后，ring buffer（`kMaxLog`）与按 tick 合并刷新是天然的背压组合，阶段 4 做 socket/管道时不要绕过 `Renderer::RenderTick`。
