## A. 语言、依赖与构建

| ID | 约束 | 理由 |
|---|---|---|
| A1 | **纯 C++ + Windows API**。不引入 Boost / libuv / asio / ncurses / PDCurses / fmt / spdlog 等第三方库 | 事件循环与 I/O 模型就是要自己实现的部分；引入现成框架等于把学习目标外包掉 |
| A2 | C++20、MSVC 为主、CMake 构建 | 需要 `std::jthread`/`std::atomic` 等现代设施；保持主流工具链 |
| A3 | 允许使用 Windows SDK 头文件与系统库（`kernel32`/`user32`/`ws2_32`/`advapi32` 等） | 这正是要学的内容 |
| A4 | 单元测试框架可自建极简断言宏，或用轻量 header-only；**不得引入需要联网下载的依赖** | 保证离线可构建 |
| A5 | 仓库不含编译产物、IDE 私有配置、密钥/token | 安全与可复现 |

## B. 线程模型（最高优先级）

| ID | 约束 | 理由 |
|---|---|---|
| **B1** | **唯一 loop 线程拥有全部可变状态**（UI 状态、连接状态、watcher 注册表、任务队列、定时器堆） | 单线程分发是事件循环的核心价值：无锁、无数据竞争、可预测 |
| **B2** | I/O 线程**只投递 completion**（`PostQueuedCompletionStatus`），绝不执行业务回调、绝不读写共享状态 | 破坏这条会立刻引入锁与竞态，退化成回调地狱 |
| **B3** | worker 线程池只做**无状态计算**（帧解析、编码转换、日志格式化、hex 转储），结果通过 `postTask` 回投 loop | 已确认需要「额外的线程池」，但必须让它保持在纯函数边界上 |
| **B4** | worker 不得持有指向 loop 状态的长生命周期指针；传值或拷贝，回投时携带结果 | 防止 use-after-free |
| **B5** | 跨线程唤醒只能经由 Waker（保留的 completion key / event handle），不得用轮询 sleep | Windows 版 self-pipe；保证 loop 可被及时唤醒 |
| **B6** | 禁止在 loop 线程上执行任何阻塞式等待（除 `GetQueuedCompletionStatusEx` 本身） | 一个阻塞点就毁掉整个事件驱动模型 |
| **B7** | 控制台输入独占一个线程，阻塞在 `ReadConsoleInput`；解析后投递 | 控制台输入句柄无法良好 overlapped，是 Win32 的经典陷阱 |

## C. 事件循环与 I/O

| ID | 约束 | 理由 |
|---|---|---|
| **C1** | 主后端用 **IOCP**（`GetQueuedCompletionStatusEx`）；阶段 5 另实现 `WaitForMultipleObjectsEx` 后端作对照 | `WaitForMultipleObjects` 的 64 句柄上限与不可重叠 I/O，是理解「Windows 为何需要 IOCP」的关键对照 |
| **C2** | 每个 Overlapped 操作必须携带独立上下文：`OVERLAPPED` + buffer + callback + generation/状态 | completion 到达时操作可能已被取消；没有上下文就无法安全分发 |
| **C3** | 实现 `uv_close` 式的 **close 状态机**：`active → closing → (排空 completion) → 释放` | 这是真实事件循环最难也最值钱的部分：回调里删 watcher、关句柄、重入分发 |
| **C4** | 关闭流程固定为 `CancelIoEx` → 排空 completion 队列 → join 线程 → 释放句柄 | 否则退出时会偶发崩溃/句柄泄漏 |
| **C5** | 不使用 `CreateTimerQueueTimer` 回调定时器（它跑在线程池线程上，破坏线程亲和性） | 定时器必须在 loop 线程分发 |
| **C6** | 定时器用**最小堆**存 deadline，堆顶作为 wait 的 timeout | 事件循环里定时器的标准答案；顺带得到 `postDelayedTask` / idle task |
| **C7** | 所有 I/O 句柄以 overlapped 方式打开并关联到 IOCP；同步 I/O 只允许出现在输入线程的 `ReadConsoleInput` | 保持模型一致 |

> **C1 落地补充（阶段 3）**：把等待环节抽象成 `IWaitBackend`（`Wake` / `Wait` /
> `Dispatch` / `Shutdown`）。`EventLoop` 默认用 `WakerBackend`（阶段 1/2 行为），
> 注入 `IocpBackend` 即切到 IOCP，阶段 5 再注入 `WaitForMultipleObjectsEx` 后端。
> `Wait()` 只从内核取包不跑回调，`Dispatch()` 才在 loop 线程执行回调 —— 这是
> 同时满足「C1 同一套接口切换后端」与「B2 回调只在 loop 线程」的关键拆分。
> 这是细化而非偏离约束。

## D. 控制台与渲染

| ID | 约束 | 理由 |
|---|---|---|
| **D1** | 主路径 legacy：`ReadConsoleInput` + `WriteConsoleOutput` + `CHAR_INFO` 双缓冲 | 学习价值最大；VT/ANSI 会绕过最精华的部分 |
| **D2** | VT/ANSI 只能作为**可选编译开关的备选后端**，不得成为默认 | 保留可移植性，但不喧宾夺主 |
| **D3** | 必须实现 **dirty-cell 差分**：前后台缓冲比较，只写变化单元格 | 逼出「事件驱动下不要每来一个字节就刷屏」 |
| **D4** | 渲染按 tick 合并；输入数据不直接触发刷新 | 背压与刷新合并是同一件事 |
| **D5** | 处理 `ENABLE_WINDOW_INPUT` / `ENABLE_MOUSE_INPUT` / resize 事件 | 否则窗口一拉就错位 |
| **D6** | 内部 UTF-16（`CHAR_INFO` 单元）；输出到 UTF-8 码页须显式转换；emoji/代理对不做保证 | 明确边界，避免被编码问题拖住 |
| **D7** | **第一版交互仅保证 ASCII 输入**；中文/IME、组合键、历史命令、光标编辑明确列为非目标 | IME 是无底洞，会抢走 runtime 的注意力 |

## E. 第一版功能边界（已确认「不要那么复杂」）

**做：**
- 连上（socket / 子进程 / 串口在 capstone）、收数据、发数据、把收到的数据显示出来。
- 若干窗格展示不同 source 的日志流；基础键盘事件（按键查看、退出键）。
- 状态栏显示事件计数 / 各 source 状态。

**不做（第一版）：**
- hex 编辑器 / 半字退格 / 帧头帧尾配置 / 多协议解析。
- 脚本、日志落盘、历史命令、Tab 补全、复杂焦点管理、鼠标拖拽。
- 配置持久化、插件系统、主题配色、多语言/IME。
- 性能极致调优（放到阶段 6）。

> 判定原则：**凡是代码量会盖过 runtime 本身的功能，一律延后。**
