# Win32 事件驱动 TUI Runtime — 项目大纲

> 用纯 C++ 与 Windows API 从零实现一套事件驱动的 TUI 运行时，并把「学会事件循环 / Windows 系统编程」作为第一目标。
>
> 本文件是**总纲**：定义「为什么做、做成什么、分几步、每步的边界」。
> 具体不可逾越的规则见 [01-约束.md](01-约束.md)；
> 每个阶段的实施记录见 [stages/](stages/) 目录，格式遵循 [docs/阶段文档模板.md](阶段文档模板.md)。

---

## 1. 目标与定位

### 1.1 学习目标（优先级最高）

1. 真正理解**事件循环**：一个线程如何同时等待多类语义不同的事件源，并把它们统一分发。
2. 掌握 Windows 特有的异步 I/O 模型：HANDLE 与 wait、Overlapped I/O、IOCP、APC、完成端口的 CompletionKey / OVERLAPPED 语义。
3. 掌握 Win32 控制台、Winsock、串口（COMM/DCB）、子进程管道等系统编程接口。
4. 建立对**异步对象生命周期**、重入（reentrancy）、背压（backpressure）、优雅关闭的工程直觉。

> 产出「能用的工具」是副产品，**不是**第一目标。任何时候两者冲突，优先保留学习价值。

### 1.2 应用载体（第一版）

**多源事件聚合控制台（Event Console）**：一个 TUI，同时挂载若干事件源，所有数据汇入环形缓冲并分窗格差分渲染，用于直观观察事件循环在跑什么。

| 编号 | 事件源 | 覆盖的 Win32 知识点 |
|---|---|---|
| S1 | 键盘 / 鼠标 / 窗口 resize | `ReadConsoleInput`、`INPUT_RECORD`、`ENABLE_WINDOW_INPUT` |
| S2 | 定时器 / 延迟任务 | 最小堆 deadline、`postTask`/`postDelayedTask`、idle task |
| S3 | 子进程 stdout/stderr 匿名管道 | `CreateProcess`、overlapped `ReadFile`、进程句柄等待、Job Object |
| S4 | 目录变更 | `ReadDirectoryChangesW`、overlapped 目录句柄 |
| S5 | TCP/UDP 监听 | Winsock、`AcceptEx`/`WSARecv` 与 IOCP 绑定 |
| S6 | 串口（可选，capstone 阶段） | `CreateFile` on `COMx`、DCB、`WaitCommEvent`、`SetCommMask` |

> **串口网络助手不做第一版应用**。原因：硬件依赖（需 com0com 虚拟串口对）、协议/hex/帧解析等 UI 细节会淹没 runtime 本身、且一次性把最难的 I/O 全压上来难以定位问题。
> 它的正确位置是**阶段 6 的 capstone**：等 Runtime 稳定后，它只是「再加两个 EventSource + 一个协议解析任务」，两三天可拼出，且那时才真正看得懂它在跑什么。

### 1.3 三项已确认决策

| 决策 | 选择 | 含义 |
|---|---|---|
| 控制台路径 | **legacy `ReadConsoleInput` + `WriteConsoleOutput`** 为主路径，VT/ANSI 仅作可选后端 | 学习价值最大；双缓冲差分渲染逼出「不要每来一个字节就刷屏」 |
| 线程模型 | **主循环单线程独占状态** + I/O 线程只投递 completion + **额外 worker 线程池** | loop 线程是唯一状态所有者；线程池只做无状态计算（帧解析/编码/格式化），结果 post 回 loop |
| 第一版功能 | **砍到最简**：连上、收发、显示 | 不做 hex 编辑、脚本、日志落盘、多协议、历史命令、复杂焦点管理 |

## 2. 整体架构

```
┌─────────────────────────── 进程 ───────────────────────────┐
│                                                              │
│  [控制台输入线程]   [Worker 线程池]   [内核 / IOCP]          │
│  ReadConsoleInput   ─ 无状态计算 ─                          │
│   INPUT_RECORD      (解析/编码/格式化)                       │
│        │                   │                                │
│        │ PostQueuedCompletionStatus / postTask               │
│        ▼                   ▼                                │
│  ┌──────────────────────────────────────────────────────┐   │
│  │              EventLoop (唯一状态所有者)               │   │
│  │  GetQueuedCompletionStatusEx ──► 分发                 │   │
│  │  ├─ TaskQueue (postTask / postDelayedTask / idle)     │   │
│  │  ├─ TimerHeap (最小堆，堆顶 = wait timeout)           │   │
│  │  ├─ EventSource/Watcher 注册表 + close 状态机          │   │
│  │  └─ RenderScheduler (dirty 合并，按 tick 刷新)         │   │
│  └──────────────────────────────────────────────────────┘   │
│        │                   ▲                                │
│        │ WriteConsoleOutput│ completion / postTask           │
│        ▼                   │                                │
│  [前台/后台 CHAR_INFO 缓冲 + dirty-cell 差分]               │
│        │                                                    │
│  ┌─────┴────────────────────────────────────────────────┐   │
│  │ EventSource 抽象（可插拔、可单独开关、可单独测）      │   │
│  │ Console | Timer | Pipe | DirWatch | Socket | (Serial) │   │
│  └────────────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────────────┘
```

### 2.1 核心不变量

- **I1 唯一所有权**：所有可变 UI / 连接状态只存在于 loop 线程；其它线程不得读写。
- **I2 只投递不回调**：I/O 线程与 worker 线程只允许 `PostQueuedCompletionStatus` / `postTask`，不得调用业务回调、不得触碰共享状态。
- **I3 completion 自带上下文**：每个 Overlapped 操作携带 `OVERLAPPED + buffer + callback + generation`；回调中删除 watcher 必须走 close 状态机。
- **I4 唤醒**：保留一个 completion key 作为 Windows 版 self-pipe，供跨线程 postTask 唤醒阻塞的 loop。
- **I5 差分渲染**：渲染按 tick 合并，输入数据不直接触发刷屏；ring buffer 有上限，溢出有明确策略。

## 5. 构建与运行约定

- 编译器：MSVC（cl.exe）为主，C++20；不依赖第三方运行时库。
- 构建：CMake；不引入 Boost / libuv / asio / ncurses 等任何「替你实现事件循环」的库。
- 字符集：Unicode（UTF-16 内部 / UTF-8 输出须显式处理）；第一版交互仅保证 ASCII 输入，中文/IME 明确列为非目标。
- 控制台：主路径 legacy console API；VT/ANSI 后端为可选编译开关。

## 6. 验收标准（第一版）

1. 单个进程内可同时挂载 ≥4 类事件源，任一源有数据都能在数帧内反映到界面。
2. 关闭任一 watcher、以及进程退出，均无 use-after-free / 句柄泄漏 / 崩溃。
3. 高吞吐输入下 UI 不掉帧、ring buffer 不无限增长（背压策略可观测）。
4. 代码里能指出：哪个函数对应「事件循环」、哪个函数对应「定时器」、哪个函数对应「I/O 通知」、哪个函数对应「刷新」。
5. 六个阶段各有一份回答三问的文档，可据此复现学习过程。

## 7. 参考方向（实现时查 MSDN，不照抄现成框架）

- IOCP：`CreateIoCompletionPort` / `GetQueuedCompletionStatusEx` / `PostQueuedCompletionStatus` / `CancelIoEx`
- 控制台：`ReadConsoleInput` / `WriteConsoleOutput` / `SetConsoleMode` / `INPUT_RECORD` 与 `CHAR_INFO`
- Overlapped：`OVERLAPPED`、`ReadFile`/`WriteFile`、`ReadDirectoryChangesW`、`WaitCommEvent`
- Winsock：`WSAStartup`、overlapped `WSARecv`/`WSASend`（或 `AcceptEx`）
- 同步：`SRWLOCK` / `CONDITION_VARIABLE` / `INIT_ONCE`、可警报等待与 APC
